# Reglas Doradas de Pruebas y QA (Testing and QA)

1. **Cobertura Mínima Aplicable por CI**: La cobertura (Code Coverage) debe estar configurada en `jest.config.ts` con `coverageThreshold` aplicado automáticamente. El umbral mínimo obligatorio para capas críticas (Servicios de dominio, Handlers de CQRS) es del **80%** en líneas y ramas. No se aceptan PRs que reduzcan la cobertura por debajo del umbral en áreas núcleo (pagos, inventario, estados de órdenes). El pipeline de CI debe fallar automáticamente si se viola. **Excepción documentada:** `field-service` no tiene suite de pruebas (ver `AGENTS.md` seción *Gotchas*); debe excluirse explícitamente del análisis de cobertura en la configuración del workspace hasta que se implemente su suite.
2. **Pruebas Unitarias Independientes**: Las pruebas unitarias (`*.spec.ts`) jamás deben conectarse a una Base de Datos real ni a un broker de RabbitMQ físico. Deben usar mocks, stubs (e.g., `jest.mock`) o repositorios en memoria, asegurando que corren en milisegundos.
3. **Pruebas de Integración y End-to-End (E2E)**: Son las únicas permitidas para probar la conectividad real con Postgres y RabbitMQ (usualmente orquestadas vía `docker-compose`). Deben ejecutarse en un entorno limpio y purgar sus datos tras finalizar para no dejar estado residual (flaky tests).
4. **Validación de Casos de Borde (Edge Cases)**: Los tests no solo deben probar el "Camino Feliz" (Happy Path). Es obligatorio crear pruebas que fuercen errores como: saldo insuficiente, errores 409 (Conflict), tokens expirados y mensajes no formateados, validando que el sistema responde de manera gracefully.
5. **Aislamiento de Tests**: Cada caso de prueba `it(...)` debe ser completamente independiente del anterior. No se debe arrastrar estado global ni variables estáticas entre una prueba y otra.
6. **Puerta de Seguridad en CI (Security Gate)**: El pipeline de CI/CD DEBE incluir `npm audit --audit-level=high` como paso obligatorio previo al despliegue. Si existen vulnerabilidades de nivel Alto o Crítico no resueltas, el pipeline debe fallar. Esto aplica el requerimiento de `data-security.md` regla 7 de forma automática y no dependiente de acción manual.
